## Raw Concept
**Task:**
Document NC Medicaid Navigator agent initialization, memory configuration, and policy guardrails inside Mastra.

**Changes:**
- Added resource-scoped working memory with a Medicaid-domain user profile and conversation preferences template.
- Converted the static system prompt into a dynamic instructions function that prepends the current date/time to every request.
- Removed the hardcoded tool count from the prompt because Mastra injects tools automatically at runtime.

**Files:**
- packages/agent/src/index.ts

**Flow:**
LibSQL storage -> Mastra Memory (observational + resource working memory) -> dynamic instructions function -> NC Medicaid Navigator agent instantiation with tools and hallucination verifier -> Mastra server exposes chat route

**Timestamp:** 2026-04-02

## Narrative
### Structure
Memory sits atop LibSQL storage; observational memory uses openai/gpt-5.4-mini while working memory is enabled per resource and seeded with the Medicaid-specific profile/preference template. Instructions are a function that captures current date/time before appending the original system guidance. The agent bundles searchSections, getSection, getDocument, getSectionContext, followReferences, getAmendments, findConceptSections, and lookupPolicy, plus the HallucinationVerifier output processor, before Mastra exposes the chat route backed by the ncMedicaidAgent.

### Dependencies
Relies on @mastra/core Mastra and Agent classes, @mastra/memory Memory, @mastra/libsql LibSQLStore, @ai-sdk/openai, @ai-sdk/anthropic for the model providers, and custom tool modules (search.js, read.js, navigate.js, concepts.js, lookup.js) plus processors/hallucination-verifier.js.

### Highlights
Seeded Medicaid working memory template, dynamic date/time instructions, explicit tool guidance for document type routing, amendment checking, and citation requirements, anti-hallucination rules, and the forced synthesis hook at MAX_STEPS-2.

### Rules
Only state facts found verbatim in retrieved sections, cite section IDs and policy numbers, prefer recent effective dates, always run getAmendments, start with searchSections, call lookupPolicy when a policy number is cited, and enforce the forced synthesis warning when approaching the MAX_STEPS ceiling.

### Examples
CLI runner invocation: `npx tsx src/index.ts "your question here"` which instantiates the agent, runs maxSteps=40, triggers the onIterationComplete warning when iterations hit 38, and prints ---ANSWER--- followed by the generated text or a fallback notice.

## Facts
- **working_memory_template**: Working memory is resource scoped and populates a Medicaid-specific template covering name, role, organization, region, detail level, and topic preferences. [project]
- **observational_memory_model**: Observational memory runs on openai/gpt-5.4-mini to capture short-term context before agent steps execute. [environment]
- **dynamic_instructions**: Agent instructions are generated by a function that prepends the current date and time via locale-specific strings when Mastra asks any question. [project]
- **tool_documentation**: The system prompt no longer lists a static tool count because Mastra injects available tools at runtime and the prompt only describes how to use them. [convention]
- **execution_limits**: MAX_STEPS is 40 with an onIterationComplete hook that forces synthesis and provides a final warning when iterations approach the limit. [convention]
