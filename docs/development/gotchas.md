# Project gotchas

- Excel formatting can extend declared dimensions to thousands of blank columns. Rendering every value from `iter_rows()` inflated ready spreadsheet text to 2.64 GB; a diagnostic preserving occupied serialized cell positions removed 90.2% of characters. Fix serialization from original cell values, preserve internal empty positions/zeros/dates, and verify regenerated artifacts before re-embedding. [Cost audit](../validation/cost-audit-sample-2026-10-03/README.md).
- The tsx CLI wrapper may spawn a fresh Node process without a parent-only fetch preloader. For a finite paid diagnostic, use native `node --import tsx --import <preloader>` and test that the executing process forwards the guard. A copied checkout also needs nested workspace dependencies.
- Loader changes must invalidate both section and chunk embedding plans, including changes to document titles and ancestor headings. A body-only cleanup can leave stale contextual vectors retrievable. Semantic document revisions now guard preflight, planning and provider-result writes. Reload unversioned source graphs before generating embeddings.
- Audit-only preparation runs write a fresh audit subdirectory and preserve the original build completion receipts. Run the identity oracle integration suite on its small disposable fixture graph; its frozen full-body query is unsuitable for a restored whole corpus.
- Offline harness socket tests must select their disposable target explicitly. CI supplies its integration `NEO4J_URI` globally; inheriting localhost in a network-isolation fixture correctly triggers the production-target rejection before its intended socket assertions. Keep those fixtures independent of ambient database settings.
- Character heuristics can substantially underprice corpus embeddings: the corrected October 3 snapshot measured 1.92 billion pinned local tokens, about $115 at Voyage 4 standard pricing. Use full shared-plan counts, never a partial scan or the old defective chunker estimate.
- Live model selection may differ from code defaults: the October 3 audit found deployed GPT-5.4 overrides and stale usage-report prices. Audit every model role, SDK endpoint and provider credential independently before a migration; catalog access does not establish generation compatibility or quality. [Audit](../validation/qualification-cycle-2026-10-03/model-audit.md).

- A full graph build can fail even with valid parses: the crawler's SQLite `datetime('now')` values contain a space, while Neo4j `datetime()` needs ISO notation. Normalize checked/changed timestamps as UTC at the write boundary, preserving plain-string retrieval times. Every caller of `MERGE_DOCUMENT` must supply every parameter it uses. A null registry title also needs the retained-filename fallback before regex matching. Use contract/regression tests plus a disposable full-corpus build. The [preparation report](../validation/qualification-preparation-2026-10-03/README.md) records the discovered failures and their verification.
- Embedding input limits include the contextual heading. The shared planner now preserves body offsets, bounds overlap, counts tokens with pinned local assets, and uses `truncation=false`; stale or incomplete saved plans invalidate their vectors before resume. Release coverage checks saved plan hashes/counts rather than a body-length threshold. The original failure was that paragraph chunking was not a hard input-size bound: a single oversized paragraph remains whole and can also be carried into the next input as overlap. Large tables expose this behavior. Before corpus embedding, complete preflight across the graph and measure the actual contextual inputs; API truncation can hide lost evidence. The [offline preparation report](../validation/qualification-preparation-2026-10-03/README.md) preserves measured outlier counts and the unresolved qualification prerequisite.
- Historical paragraph chunking preserved oversized paragraphs and repeated entire paragraphs as overlap, producing inputs up to 38 MB. The shared contextual token planner now bounds all inputs and checks exact body coverage; generation and release inspection must use the same plan. Include headings in sizing, preserve ordered repeated ancestor titles, and refuse unversioned vectors. Spreadsheet fee schedules contain substantial empty-cell padding: valid chunk sizes do not establish useful representation, low cost, or bounded returned evidence. See [embedding input plans](../operations/embedding-input-plans.md).
- Coverage mocks must replace the shared `embeddings.plan_graph` reader/checker, not only `generator.get_session`; otherwise a coverage test can read the default local graph. Real embedding integration requires its dedicated empty disposable graph and mocked Voyage, separate from corpus and other integration fixtures.

Current guidance carried forward from main at `dc81a97`. When behavior changes, correct the affected lesson alongside the implementation.

- Production browser smoke identifies restored conversations by exact titles. Duplicate generated titles make that check ambiguous even after verification passes. Run account-based smoke serially. The script now renames the thread it recorded creating to a unique `smoke <timestamp>` title before the switch/reload checks and deletes it after a pass; a failed run keeps its thread. Retain failed receipts separately.
- A synthetic WorkOS account on `example.com` can match an SSO domain policy and reject password authentication with `sso_required`, despite verified email. Use a reserved fixture domain that permits the tested method. Retain safe error codes and clean up accounts created by the run; do not change authentication policy to make acceptance pass.
- Railway SSH can exit successfully while returning account/control metadata instead of executing a container command. Confirm an explicit command sentinel and the intended service/deployment before relying on output or cleanup. Public route checks exercise active storage behavior, but do not establish private observer inputs or signing-key continuity.


- eCFR HTTP 406 can affect full text even when the title index works, so `fetch_part_xml` reads GovInfo first and falls back to the eCFR API only when a title's GovInfo file cannot be used. GovInfo publishes current whole-title eCFR XML; validate its title header, extract exactly one configured part, and preserve retrieval provenance before caching. Its section `N` attributes include `§`/`§§`, including reserved ranges: normalize these markers before the existing parser, or canonical section IDs change. Never substitute annual CFR editions or accept maintenance HTML as current regulatory content.
- Identity normalization must page node IDs before joining full section, parent and sibling bodies. Keep every graph section and ambiguity check, compact bodies into the same matching signatures, and reject interrupted or changed scans; filtering to benchmark IDs can conceal duplicates. Compare a frozen prior-implementation oracle and real Neo4j fixtures before interpreting live mapping diagnostics.
- Docling loader tests select a top-level JSON fixture. Keep unrelated identity/evaluation fixtures in their own subdirectories, so adding an oracle does not change which document the loader tests parse.

- Statute text comes from GovInfo's Statute Compilations (`COMPS-8765` for SSA Title XIX, `COMPS-8770` for Title XXI; `packages/pipeline/src/pipeline/federal/ssa_client.py`), not `uscode.house.gov`, which stored editorial notes and future amendments as statute text and answered HTTP 200 maintenance pages in October 2026. Successful transport still does not establish statutory content: validate the compilation's root element, title and required section anchors before replacing or consuming a cache, and keep the previous bytes and modification time on response rejection. Invalid caches trigger a fresh fetch, and failed CFR/SSA ingestion exits nonzero so dependent operator commands stop. The compilation's `processedDate` is not a freshness measure (Title XXI was processed in February 2026 and is current through P.L. 119–75); its `currentThroughPublicLaw` is, and the loader writes it into the Document title.
- The compilations execute an amendment into the text as soon as it is in force, even when it applies only to later applications or periods, and they say nothing about the applicability date: section 1902(a)(34) reads with the P.L. 119-21 retroactive-coverage wording (one month, or two for non-expansion groups), which governs applications made on or after 1 January 2027, and the "third month" rule in force until then appears nowhere in the file. Amendments with a delayed *effective* date are held out and footnoted instead (P.L. 119-75 §6101(b), effective 2029). Read a statute citation with that in mind until 2027, and do not treat the compilation as a source of effective dates. The coverage rehearsal also received eCFR full-text HTTP 406 responses from both local and Railway hosts; a working title-index endpoint does not prove full-text access. Neither response establishes withdrawal or fresh federal evidence.

- Non-PDF parse artifacts use format-qualified stems (`notice__html.json`, not `notice.json`). Scope approval and encrypted-backup dependency checks must use the shared lightweight artifact naming helper, rather than strip the source extension. The coverage rehearsal exposed a mismatch hidden by hand-written unit fixtures; acceptance now exercises actual HTML parser output.

- Drupal bulletin pages can place the document `h1` before the semantic `article`, with the enclosing `main` linked to it through `aria-labelledby`. Requiring an article-local title rejected the full September 25, 2024 COVID bulletin during the coverage rehearsal. Accept the explicitly associated heading only for a single article with one matching heading; keep unrelated page headings, conflicting article titles and ambiguous articles rejected. The declared COVID bulletin must also contain its reviewed OTC-testing heading and coverage-end statement inside the article; a branded error with the expected page title is insufficient. Article body extraction remains confined to the semantic article, and scope fingerprints include the downloader, discovery code and manifest.

- Classify research coverage at the user-question API boundary, not on internal reflection prompts containing findings and quotations. Reject unsupported requests before creating a run/consuming quota, and independently enforce the original question during final-report verification.
- Mastra 1.58: a per-call `inputProcessors: []` replaces the agent's processors rather than adding to them, which is how the reflection call keeps the planner's chat-input guards off its own findings prompt. `generate` with `structuredOutput` throws on a schema mismatch unless `errorStrategy: 'warn'` is set, so a `safeParse` on `res.object` alone is not a fallback. `generate` calls the model's `doGenerate`, not `doStream`; mock models in tests must implement `doGenerate`.
- The polled research run's `plan.subQuestions` is the approved list plus reflection follow-ups (the `follow-ups` checkpoint), so the in-flight count is accurate. Follow-ups appear only once an approval is stored; the stored approval itself never includes them, and recovery reads the approval, not the public plan.
- Plan approval is prune-only. `POST /research/runs/:runId/decision` takes `keptSubQuestions`, positions in the stored plan, and `ResearchService.decide` resolves them to the planner's own questions; the request schema is strict and has no field for question text. The question is screened for client identifiers and coverage at the start route only, so do not add an approval field that carries text to a worker without screening it the same way. The stored approval (`ResearchApprovalSchema`, still keyed `editedSubQuestions`) is built by the server alone.
- Only an approved run (`approval_json IS NOT NULL`) consumes one of the two daily research reports, whatever happens to it afterwards; every created run counts toward the separate cap of six plans per 24 hours. Both are checked in the `create()` insert. Do not exempt approved runs that later failed or were cancelled: approve, let workers run, cancel would then be free paid work. Neither limit is rechecked at approval, and both windows run from creation time: a third run is refused at creation while two approved runs are in the window, and one active run per user means no extra plan can be waiting to be approved, so at most two runs created in any 24 hours can be approved. Changing either the create-time check or the one-active-run rule means rechecking the limit at approval. A plan approved late in its 24-hour life leaves the window soon after, so three reports can fall close together, but the waiting plan held the user's only active slot meanwhile and the long-run rate does not rise.
- Leaving the Deep Research view never touches the run. Switching thread, "+ New" and the Deep Research pill only change what `chat/page.tsx` shows: the hook keeps polling and keeps a finished report for the session, and the pill reads "running", "plan ready" or "report ready" while the view is hidden. The page turns the view on once, when the hook's status leaves `idle` (a start, or the run found at page load); forcing it on whenever a run exists makes thread selection appear to do nothing. A run is cancelled only by the buttons inside the view (`cancel`, `decline`, and `reset` behind "Start over" and "Try again"). Do not call `reset()` from navigation.
- `ResearchService` cancels the run row first and its Mastra workflow second. `workflow_run_id` is cleared only when the workflow cancel succeeds, and the 60-second sweep retries every cancelled run that still has one (`pendingWorkflowCancels`) for a day. Keep the column set on failure; clearing it early loses the retry.
- The server owns the deep-research run id: the page asks `GET /research/runs/current` on load and after a 409 `active_research_run`, and keeps no browser-stored copy. Register that route before `/research/runs/:runId`, which also matches `current`. A plan left `awaiting_approval` has no lease, so the 60-second recovery sweep cancels it after 24 hours; without that it holds the owner's single active-run slot until retention deletes it.
- Scope approval must bind the complete corpus after excluding only its own scope records; checking selected supporting artifacts alone leaves unrelated source changes undetected. Rerun native archive decryption/restore verification before first approval, and retain its independently checked receipt. Conversational date follow-ups and language-access questions need explicit boundary tests; a historical coverage-end notice alone cannot prove current payment applicability. See the [scope procedure](../operations/answer-coverage-scope.md).
- Source-family `required_for_answering` is an operational gate, not a document-specific product-coverage assessment. Available related documents do not prove a missing original was duplicated or withdrawn. Grounding also does not establish current applicability: retained OTC COVID guidance describes ongoing POS coverage, while an official September 2024 bulletin records its end date. The [product scope review](../validation/product-scope-review-2026-10-03/README.md) supplies review evidence; the [scope procedure](../operations/answer-coverage-scope.md) requires exact identities, complete dated evidence, matching tested backups, durable separate accounting and repeated live acceptance. Code or unit tests alone do not approve a production exclusion.
- `resolveCoverageScope` runs before the model and its notice ends the turn, so a loose pattern is a refusal the user cannot rephrase around. Until October 2026 it read "$2000 a month" and "born in 2015" as the requested year, matched "table" inside "portable", and treated any COVID question mentioning "at home" as the OTC-test payment question. None of the 105 benchmark questions resolves to a scope, so only the cases in `packages/policy-corpus/tests/answer-scope.test.ts` detect this; add the sentence there when changing a pattern. A stated year outside the supported tables still fails closed, even when it belongs to another clause. The same file holds a real-clock test that fails once the latest `magi_tables[].supported_until` in `scope/policy.json` is fewer than 45 days away (from 2026-11-16 UTC for the 2026-12-31 bound): it is a deliberate tripwire, fixed by the review in the [scope procedure](../operations/answer-coverage-scope.md) and a new date, not by editing the test. `coverage.ts` and `coverage-boundary.ts` are inputs to `implementation_hash()` and `policy.json` is the policy hash, so any edit to them invalidates stored scope approvals; batch such edits.
- Materializing encrypted corpus archives must preserve original file timestamps. Federal cache freshness uses modification times; assigning extraction-time timestamps can make old bytes appear fresh. Verify original cache hashes and timestamps against the retained archive, and never use an extraction timestamp as fetch evidence. The [October 3 rehearsal](../validation/coverage-rehearsal-2026-10-03/README.md) corrected this helper error before its final backup.
- Successful federal HTTP transport does not establish source content. The October 3 rehearsal received USC maintenance pages with status 200, and eCFR full-text requests returned 406 even where the title index worked. [PR #199](https://github.com/Queen-City-Cortex/medicaid-agent/pull/199) adds statute-content validation and nonzero failed-import exits; its isolated tests do not establish deployed behavior or source freshness.
- The full legacy evaluation identity query can exhaust Neo4j direct memory before normalization returns any mapping. Retain the infrastructure failure and establish a complete successful mapping before reporting missing/ambiguous identities or benchmark scores; do not treat a partial query as a regression result. See the [rehearsal blocker ledger](../validation/coverage-rehearsal-2026-10-03/qualification-blockers.json).

- Mastra merges non-reserved body and GET-query `requestContext` keys before application middleware and custom routes. Dropping client execution options in the chat handler does not clear those already-merged values. The legacy `user` key is client-mergeable too: bind resource ownership only from the verified token and clear it on missing or invalid authentication. Overwrite server-owned verification, diagnostic and prior-turn context on every request, including when diagnostics are disabled or the thread is new; HTTP fixtures must simulate the framework merge before testing forged context rejection.

- What Mastra passes an input processor's `messages` depends on the memory mode: with observational memory on it is the newest message alone, with it off (the default since October 2026) it is the recalled history plus the newest message. A gate that needs earlier turns must not read them from `messages`; unit tests that hand a processor a multi-message array hide this. The chat route reads the newest stored turns after the ownership check and sets them on the server-owned `chatPriorTurns` key, and `withPriorTurns` in `packages/agent/src/processors/prior-turns.ts` combines them with `messages` without counting a turn twice. Regressions belong at the HTTP level, in both memory modes (`tests/chat-prior-turns-http.test.ts`). The prompt-injection detector is built with `lastMessageOnly: true`; without it, memory-off recall costs one classifier call per recalled message and an old answer can block every later turn.
- A classifier that refuses an oversized input turns input size into a way through a gate that fails open. The Jev client rejects a body over 30,000 UTF-8 bytes, which about 9,990 CJK or Gujarati characters exceed; bound the bytes at the call site (`fitScopeWindow` in `packages/agent/src/jev/scope.ts`) and test with multi-byte text, not ASCII.
- The AI-SDK chat adapter does not perform the memory API's thread-ownership check before observational memory loads history. Binding the correct resource ID alone can still let a supplied foreign thread reach the observer. Check the existing thread's owner in the custom chat handler before starting execution; regressions must inspect observer/model inputs and stored history, not just the withheld public answer.
- Mastra's built-in memory routes do not fully enforce thread ownership on server 1.45.0 / libSQL 1.14.0. `POST /api/memory/threads` skips the owner check for an existing id and the adapter writes with `INSERT OR REPLACE`, so a create could re-own another user's thread; `GET /api/memory/threads/:id/messages?include=...` resolves message ids with no owner filter. The gateway no longer exposes the create route at all (see the next entry), but the agent's own create on `/chat` reaches the same adapter write. Two local guards are load-bearing: the `saveThread` wrapper in `installMemoryReleaseGate` refuses a write that changes an existing thread's `resourceId`, and the execution gateway returns 400 for `include`. The release gate's read wrappers do not cover the second gap, because they only rewrite assistant text. Keep both guards, and the two-user case in `chat-memory-http.test.ts`, across Mastra upgrades until upstream scopes both paths.
- No client creates a chat thread. The browser picks an id and sends it on `/chat`; the route passes Mastra `memory.thread` as `{ id, title }`, with the title cut from the first 60 characters of the screened question, and the route itself saves the thread row when the id has none. That runs after the identifier screen, the rate limit and the ownership check, so a message refused by any of them stores nothing, and a redacted phone number appears in a title only as its marker. The gateway answers `POST /api/memory/threads` with 404; do not restore it, because the framework's create route screens nothing and the web used it to store the first 60 characters of a question the screen then refused. Some consequences. The thread exists before the input processors run, so a first message stopped by the length guard, the scope gate or the injection detector leaves a thread row with the screened title and no messages. The route saves the row rather than leaving it to the framework: when Mastra creates a thread itself it writes the row again at the first step and at the end of that turn (`INSERT OR REPLACE`, same owner, the title it read at the start), which overwrites a rename made while the first answer is streaming and restores a thread the user deleted. With the row already present the framework never rewrites it. The sidebar lists the thread mid-answer only after a thread switch or "+ New" re-reads the list, or in a second tab. And an existing thread keeps its title: later turns, and a turn after a rename, do not write it. `generateTitle` is off (the framework default, which `createChatMemory` leaves alone); turning it on would send the question to the agent's model a second time for a title. The sidebar learns of a new thread when the turn ends (`threadVersion` in `use-chat-thread.ts`), not when it starts.
- Thread request bodies are an allow-list in the execution gateway (`UPDATE_THREAD`, `CLONE_THREAD` in `packages/agent/src/execution-gateway.ts`): a rename takes `title` alone, a copy takes `title` and `resourceId`, and any other key, `metadata` above all, is a 400. The framework stores client `metadata` as sent (update and clone both pass it through) and gives `metadata.mastra.om` to the observer and the model as system text, past every input guard. A `resourceId` on a copy must equal the signed-in user. A new field the web needs on a thread request must be added to these schemas or the request fails. The gateway reads the body from `c.req.raw.clone()`, as the framework's own context middleware does: reading it through `c.req.text()` consumes the stream, and the per-route `bodyLimit` then throws a 500 on any request without a `Content-Length` header (every `app.request` test, and chunked requests in production). Do not await `cancel()` on a cloned body's reader; it settles only when the original is cancelled too.
- Mastra's memory handlers answer a failure with the raw error text (`{"error":"SQLITE_ERROR: no such table: mastra_threads"}`). The gateway replaces every 4xx/5xx body from the `/api/memory/threads` routes with a fixed `{ error: { code, message } }` at the same status and logs `memory_route.failed` (5xx, with the original text) or `memory_route.refused` (4xx, status only, because a validation message can quote the request). The log names the route pattern, not the path, since the path holds a client-chosen thread id. When a thread route fails in a test, read that log line; the response no longer says why.
- `packages/agent/tests/server-isolation.test.ts` is the cross-user contract on the real server: `bootProductionServer` (`tests/helpers/production-server.ts`) builds the app from `createAgentRuntime` and `createHonoServer` over a temporary LibSQL file, and two users try every route with each other's ids. Its sweep walks `app.routes`: every route behind the gateway must answer the gateway's own 404 body to a signed-in user and to nobody, or its 401 and appear in the test's `OWNED_ROUTES`; the memory routes and the `/api/*` families are listed exactly. After a Mastra upgrade the failure message names each route to classify: read what the new route does before adding it to a list, and add a two-user case for any route the gateway is opened to. The five bare-Hono chat tests still use `tests/helpers/client-request-context.ts`, a hand copy of the merge described above that nothing checks against the framework, so re-read the merge after an upgrade.
- `createHonoServer` (deployer 1.45.0) registers four framework routes before `server.middleware`, so the resource binding and the execution gateway never run for them: `GET /health`, `GET /api/agents/:agentId/browser/session`, `POST /api/agents/:agentId/browser/close` and the WebSocket upgrade on `GET /browser/:agentId/stream`. Left alone they answer without a token, and the upgrade completes for anyone. No server option turns them off (without `@hono/node-ws` the session route is still registered, and `/health` always is). `refuseFrameworkRoutes(mastra)` in `packages/agent/src/runtime.ts` answers the gateway's 404 on those paths through `mastra.setServerMiddleware`, the one hook the server registers earlier (right after its context middleware); `src/index.ts` and the test harness both call it on the instance they build. Pass the path `'*'`: a bare handler defaults to `/api/*` and would miss `/health` and the stream route. The refusal is a list (`ROUTES_AHEAD_OF_GATEWAY` in `execution-gateway.ts`), not a rule, so the isolation test pins the set registered ahead of the gateway: a fifth route added by an upgrade fails that test and stays open until it is listed, and an upgrade that stops calling `getServerMiddleware` fails the four refusal cases. `/health` is refused, not public: Railway probes `/readyz` and the ops scripts `/healthz`. The refusal runs before the CORS middleware, so its 404 carries no CORS headers.
- What the installed server takes from a client before application code runs (read from `@mastra/deployer` and `@mastra/server` 1.45.0, and exercised by the isolation test): `requestContext` in a JSON body on POST and PUT only (not PATCH or DELETE), `requestContext` in a GET query as JSON or base64, and `x-mastra-client-type: studio`, which sets `mastra__isStudio`. Route-level authentication also accepts the token from an `?apiKey=` query and from an `Authorization` header without the `Bearer` scheme; the binding middleware accepts neither, so such a request has no bound user and the gateway answers 401. `x-mastra-dev-playground` skips authentication only when `MASTRA_DEV=true` and the server has no auth provider.
- Booting the runtime twice in one process: `configureAnswerRelease` holds one module-wide signing key, so a second `createAgentRuntime` on another database replaces it and the first runtime's stored answers then read back as unverified. Give each boot its own `describe` and close the first before the second starts. A fresh store has no tables until the first request; call `runtime.storage.init()` before writing to it directly. `boolEnv('ALLOW_MASTRA_STUDIO')` and the gateway's production guard read `process.env`, not the `env` argument, so stub them with `vi.stubEnv` before the boot.
- `screenUserText` (`packages/agent/src/sensitive-data.ts`) is the one screen for user-written text; the chat route, the research start route and the feedback route all call it and keep only the `text` it returns. It replaces phone numbers and e-mail addresses with `[phone number removed]` and `[email removed]` and does not refuse them, because a quoted notice carries agency and legal-aid numbers; a Social Security number, a labelled birth date or a labelled member ID is still refused with 422 `client_identifier_detected`. Redaction runs before the refusal rules, so "the Medicaid number is 888-245-0179" loses the number and is answered. The chat route rebuilds the newest user message as one text part holding the screened text and puts the same string on `chatVerificationQuestion`, so storage, the input gates, the model, the verifier and private diagnostics never hold the original; `tests/chat-identifier-redaction-http.test.ts` checks each of those. The browser still shows what the user typed until the thread is reloaded, and it sets the thread title from the unscreened first 60 characters before `/chat` runs (card PRIV-3). The birth-date and member-ID rules need a label, so an unlabelled date, a birth date written with a month name and "born on" are not caught. Keep each pattern to one repeating run of spaces after the label: `\s*[:#-]?\s*` reads a long blank run quadratically, and the input can be 10,000 characters.
- Feedback: `POST /feedback` also requires the caller to own the thread (`FeedbackRepository.ownsThread`); it does not check that the message exists, because the assistant row can be saved after the stream ends and a quick thumbs click would race it. `scripts/feedback-review.ts` therefore joins feedback to a thread with the same owner and prints a rating whose message id is not in the store with a placeholder. It reads answers through `guardMessage`, so it needs the `answer_release_keys` row from the same database; against a copy without that row every answer prints as the unverified-history notice.
- The memory release gate replaces named methods on the LibSQL memory store, so it is default-deny: `installMemoryReleaseGate` walks the store's whole prototype chain and throws at start-up when a function is in neither `GUARDED_MEMORY_METHODS` nor `PASS_THROUGH_MEMORY_METHODS` (`packages/agent/src/answer-release.ts`). A Mastra upgrade that adds a store method (`copyThread`, `updateThreadMetadata` and `updateThreadResourceId` arrive with core 1.67 / libSQL 1.23) therefore fails the agent tests and the boot until someone decides whether the method can return or persist assistant prose or change a thread's owner. Do not classify a new name as pass-through to get the server up without reading its adapter source; `updateThreadResourceId` in particular needs the same owner guard as `saveThread`.
- `GET /api/memory/threads/:id/messages` returns 40 messages unless `perPage` is sent, has no maximum page size, and with no `orderBy` returns the newest page. `orderBy` only picks which window of rows a page covers: Mastra's `MessageList` re-sorts every page oldest first, so a `DESC` request does not return rows newest first. Offsets carry no tiebreak on `createdAt` and shift when a message is stored between two requests, so page through `packages/web/src/lib/thread-messages.ts`, which de-duplicates by id and trusts `hasMore` rather than the page length. The client's response type omits `hasMore` and `total`; the server sends them.

- `source-audit-collect` caches captures by URL across its selected rows. Additional investigation URLs shared across different source families can be rejected by the first row's domain policy and then remain cached as errors for later rows. Collect supplementary official identity evidence in a separate audit containing only the matching family, and validate the selected rows against a fresh locked registry snapshot. A rejected request is not evidence that the official page or payload is unavailable.
- Private Python helpers can shadow standard-library modules: a temporary `select.py` caused `subprocess` imports to execute the helper locally. Use descriptive filenames or run helpers with `python3 -P`; keep recovery helpers separate from importable package code.
- An existing corpus registry without `crawler/recovery-journal` is incomplete. Do not recreate that directory as empty at startup: a later mirror sync could erase the only remaining remote history. Restore the journals explicitly. Completed relocation proof also needs the installed payload, or its retained version plus the valid current artifact after a later revision.
- Removed source rows still own their retained original payloads. Reconciliation must preserve those files along with `.versions` and `.recovery-evidence`; treating removed originals as unowned breaks retirement evidence and later recovery. Check removed identities without reactivating or quarantining their originals.

- Parse inventory alone cannot find downloads that never created a `local_path`. Reconcile every non-removed registry row as well: September 2026 had 33 such failures (30 optional fee-schedule/guidance attachments and three required DHHS wrappers). `recovery-inventory` includes these and release preparation rejects missing required payloads before parsing or graph reset. The final complete inventory also exposed 283 existing optional parse exceptions, for 313 optional failures including downloads; report them separately without silently weakening source-family requirements.

- The corpus-job image pins Railway CLI 5.17.0, which has no `railway api` subcommand even though a newer workstation CLI does. Initial activation uses the public GraphQL API with the project token header; validate operational adapters against the production image, not just local CLI help.

An entry holding part of a section carries a `Chars: a-b of N` line and the key `<section id>#chars=a-b` (deep research keeps the first entry per key); a whole section keeps the bare id. Windows of one section that touch or overlap, from `getSection` or the frame, are joined into one entry in `extractSourcesFromToolResults`, because the quotation check searches entries' text and a quotation across a window boundary is contiguous only in a joined entry. ## Pipeline dead-code detection


`npm run lint -w @nc-medicaid/pipeline` runs **both** `ruff check src/` **and** `vulture src vulture_whitelist.py`. Vulture exits non-zero on *any* finding, so introducing dead Python code (or a vulture false positive) fails lint.

`packages/pipeline/vulture_whitelist.py` is a **curated** list of confirmed false positives — things vulture can't see are used: Click CLI commands (`@cli.command`), `HTMLParser` method overrides, driver/library attributes (e.g. `row_factory`), symbols referenced only by tests, and `SourceFamilyManifest` schema fields populated from `corpus-manifest.json`. If lint flags one of these for new code, add it to the whitelist.

Do **not** regenerate the whitelist with a bare `vulture src --make-whitelist` and commit it wholesale — that silently buries genuine dead code (it once would have hidden ~12 dead query constants). Use `--make-whitelist` to produce *candidates*, then triage: real dead code gets deleted, only true false positives go in the whitelist. The whitelist is excluded from ruff (`extend-exclude` in `pyproject.toml`) since its bare names would trip F821.
