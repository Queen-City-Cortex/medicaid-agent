# Project gotchas

- Excel formatting can extend declared dimensions to thousands of blank columns. Rendering every value from `iter_rows()` inflated ready spreadsheet text to 2.64 GB; a diagnostic preserving occupied serialized cell positions removed 90.2% of characters. Fix serialization from original cell values, preserve internal empty positions/zeros/dates, and verify regenerated artifacts before re-embedding. [Cost audit](../validation/cost-audit-sample-2026-10-03/README.md).
- The tsx CLI wrapper may spawn a fresh Node process without a parent-only fetch preloader. For a finite paid diagnostic, use native `node --import tsx --import <preloader>` and test that the executing process forwards the guard. A copied checkout also needs nested workspace dependencies and inert WorkOS redirect settings even when running CLI-only.
- Loader changes must invalidate both section and chunk embedding plans, including changes to document titles and ancestor headings. A body-only cleanup can leave stale contextual vectors retrievable. Semantic document revisions now guard preflight, planning and provider-result writes. Reload unversioned source graphs before generating embeddings.
- Audit-only preparation runs write a fresh audit subdirectory and preserve the original build completion receipts. Run the identity oracle integration suite on its small disposable fixture graph; its frozen full-body query is unsuitable for a restored whole corpus.
- Offline harness socket tests must select their disposable target explicitly. CI supplies its integration `NEO4J_URI` globally; inheriting localhost in a network-isolation fixture correctly triggers the production-target rejection before its intended socket assertions. Keep those fixtures independent of ambient database settings.
- Character heuristics can substantially underprice corpus embeddings: the corrected October 3 snapshot measured 1.92 billion pinned local tokens, about $115 at Voyage 4 standard pricing. Use full shared-plan counts, never a partial scan or the old defective chunker estimate.
- Live model selection may differ from code defaults: the October 3 audit found deployed GPT-5.4 overrides and stale usage-report prices. Audit every model role, SDK endpoint and provider credential independently before a migration; catalog access does not establish generation compatibility or quality. [Audit](../validation/qualification-cycle-2026-10-03/model-audit.md).

- A full graph build can fail even with valid parses: the crawler's SQLite `datetime('now')` values contain a space, while Neo4j `datetime()` needs ISO notation. Normalize checked/changed timestamps as UTC at the write boundary, preserving plain-string retrieval times. Synthetic amendment documents must supply every parameter used by `MERGE_DOCUMENT`. A null registry title also needs the retained-filename fallback before regex matching. Use contract/regression tests plus a disposable full-corpus build. The [preparation report](../validation/qualification-preparation-2026-10-03/README.md) records the discovered failures and their verification.
- Embedding input limits include the contextual heading. The shared planner now preserves body offsets, bounds overlap, counts tokens with pinned local assets, and uses `truncation=false`; stale or incomplete saved plans invalidate their vectors before resume. Release coverage checks saved plan hashes/counts rather than a body-length threshold. The original failure was that paragraph chunking was not a hard input-size bound: a single oversized paragraph remains whole and can also be carried into the next input as overlap. Large tables expose this behavior. Before corpus embedding, complete preflight across the graph and measure the actual contextual inputs; API truncation can hide lost evidence. The [offline preparation report](../validation/qualification-preparation-2026-10-03/README.md) preserves measured outlier counts and the unresolved qualification prerequisite.
- Historical paragraph chunking preserved oversized paragraphs and repeated entire paragraphs as overlap, producing inputs up to 38 MB. The shared contextual token planner now bounds all inputs and checks exact body coverage; generation and release inspection must use the same plan. Include headings in sizing, preserve ordered repeated ancestor titles, and refuse unversioned vectors. Spreadsheet fee schedules contain substantial empty-cell padding: valid chunk sizes do not establish useful representation, low cost, or bounded returned evidence. See [embedding input plans](../operations/embedding-input-plans.md).
- Coverage mocks must replace the shared `embeddings.plan_graph` reader/checker, not only `generator.get_session`; otherwise a coverage test can read the default local graph. Real embedding integration requires its dedicated empty disposable graph and mocked Voyage, separate from corpus and other integration fixtures.

The script now renames the thread it recorded creating to a unique `smoke <timestamp>` title before the switch/reload checks and deletes it after a pass; a failed run keeps its thread. Retain failed receipts separately.

Use a reserved fixture domain that permits the tested method. Retain safe error codes and clean up accounts created by the run; do not change authentication policy to make acceptance pass.

Confirm an explicit command sentinel and the intended service/deployment before relying on output or cleanup. Public route checks exercise active storage behavior, but do not establish private observer inputs or signing-key continuity.


- eCFR HTTP 406 can affect full text even when the title index works. GovInfo publishes current whole-title eCFR XML; validate its title header, extract exactly one configured part, and preserve retrieval provenance before caching. Its section `N` attributes include `§`/`§§`, including reserved ranges: normalize these markers before the existing parser, or canonical section IDs change. Never substitute annual CFR editions or accept maintenance HTML as current regulatory content.
- Identity normalization must page node IDs before joining full section, parent and sibling bodies. Keep every graph section and ambiguity check, compact bodies into the same matching signatures, and reject interrupted or changed scans; filtering to benchmark IDs can conceal duplicates. Compare a frozen prior-implementation oracle and real Neo4j fixtures before interpreting live mapping diagnostics.
- Docling loader tests select a top-level JSON fixture. Keep unrelated identity/evaluation fixtures in their own subdirectories, so adding an oracle does not change which document the loader tests parse.

- `uscode.house.gov` can return an HTTP 200 maintenance page for full SSA subchapter requests. Successful transport does not establish statutory content. Validate substantive required section anchors before replacing or consuming a cache; keep the previous bytes and modification time on response rejection. Invalid caches trigger a fresh fetch, and failed CFR/SSA ingestion exits nonzero so dependent operator commands stop. The coverage rehearsal also received eCFR full-text HTTP 406 responses from both local and Railway hosts; a working title-index endpoint does not prove full-text access. Neither response establishes withdrawal or fresh federal evidence.

- Non-PDF parse artifacts use format-qualified stems (`notice__html.json`, not `notice.json`). Scope approval and encrypted-backup dependency checks must use the shared lightweight artifact naming helper, rather than strip the source extension. The coverage rehearsal exposed a mismatch hidden by hand-written unit fixtures; acceptance now exercises actual HTML parser output.

- Drupal bulletin pages can place the document `h1` before the semantic `article`, with the enclosing `main` linked to it through `aria-labelledby`. Requiring an article-local title rejected the full September 25, 2024 COVID bulletin during the coverage rehearsal. Accept the explicitly associated heading only for a single article with one matching heading; keep unrelated page headings, conflicting article titles and ambiguous articles rejected. The declared COVID bulletin must also contain its reviewed OTC-testing heading and coverage-end statement inside the article; a branded error with the expected page title is insufficient. Article body extraction remains confined to the semantic article, and scope fingerprints include the downloader, discovery code and manifest.

- Classify research coverage at the user-question API boundary, not on internal reflection prompts containing findings and quotations. Reject unsupported requests before creating a run/consuming quota, and independently enforce the original question during final-report verification.
- Mastra 1.58: a per-call `inputProcessors: []` replaces the agent's processors rather than adding to them, which is how the reflection call keeps the planner's chat-input guards off its own findings prompt. `generate` with `structuredOutput` throws on a schema mismatch unless `errorStrategy: 'warn'` is set, so a `safeParse` on `res.object` alone is not a fallback. `generate` calls the model's `doGenerate`, not `doStream`; mock models in tests must implement `doGenerate`.
- The polled research run's `plan.subQuestions` is the approved list plus reflection follow-ups (the `follow-ups` checkpoint), so the in-flight count is accurate. Follow-ups appear only once an approval is stored; the stored approval itself never includes them, and recovery reads the approval, not the public plan.
- Plan approval is prune-only. `POST /research/runs/:runId/decision` takes `keptSubQuestions`, positions in the stored plan, and `ResearchService.decide` resolves them to the planner's own questions; the request schema is strict and has no field for question text. The question is screened for client identifiers and coverage at the start route only, so do not add an approval field that carries text to a worker without screening it the same way. The stored approval (`ResearchApprovalSchema`, still keyed `editedSubQuestions`) is built by the server alone.
- Only an approved run (`approval_json IS NOT NULL`) consumes one of the two daily research reports, whatever happens to it afterwards; every created run counts toward the separate cap of six plans per 24 hours. Both are checked in the `create()` insert. Do not exempt approved runs that later failed or were cancelled: approve, let workers run, cancel would then be free paid work. Neither limit is rechecked at approval, and both windows run from creation time: a third run is refused at creation while two approved runs are in the window, and one active run per user means no extra plan can be waiting to be approved, so at most two runs created in any 24 hours can be approved. Changing either the create-time check or the one-active-run rule means rechecking the limit at approval. A plan approved late in its 24-hour life leaves the window soon after, so three reports can fall close together, but the waiting plan held the user's only active slot meanwhile and the long-run rate does not rise.
- The server owns the deep-research run id: the page asks `GET /research/runs/current` on load and after a 409 `active_research_run`, and keeps no browser-stored copy. Register that route before `/research/runs/:runId`, which also matches `current`. A plan left `awaiting_approval` has no lease, so the 60-second recovery sweep cancels it after 24 hours; without that it holds the owner's single active-run slot until retention deletes it.
- Scope approval must bind the complete corpus after excluding only its own scope records; checking selected supporting artifacts alone leaves unrelated source changes undetected. Rerun native archive decryption/restore verification before first approval, and retain its independently checked receipt. Conversational date follow-ups and language-access questions need explicit boundary tests; a historical coverage-end notice alone cannot prove current payment applicability. See the [scope procedure](../operations/answer-coverage-scope.md).
- Source-family `required_for_answering` is an operational gate, not a document-specific product-coverage assessment. Available related documents do not prove a missing original was duplicated or withdrawn. Grounding also does not establish current applicability: retained OTC COVID guidance describes ongoing POS coverage, while an official September 2024 bulletin records its end date. The [product scope review](../validation/product-scope-review-2026-10-03/README.md) supplies review evidence; the [scope procedure](../operations/answer-coverage-scope.md) requires exact identities, complete dated evidence, matching tested backups, durable separate accounting and repeated live acceptance. Code or unit tests alone do not approve a production exclusion.
- Materializing encrypted corpus archives must preserve original file timestamps. Federal cache freshness uses modification times; assigning extraction-time timestamps can make old bytes appear fresh. Verify original cache hashes and timestamps against the retained archive, and never use an extraction timestamp as fetch evidence. The [October 3 rehearsal](../validation/coverage-rehearsal-2026-10-03/README.md) corrected this helper error before its final backup.
- Successful federal HTTP transport does not establish source content. The October 3 rehearsal received USC maintenance pages with status 200, and eCFR full-text requests returned 406 even where the title index worked. [PR #199](https://github.com/Queen-City-Cortex/medicaid-agent/pull/199) adds statute-content validation and nonzero failed-import exits; its isolated tests do not establish deployed behavior or source freshness.
- The full legacy evaluation identity query can exhaust Neo4j direct memory before normalization returns any mapping. Retain the infrastructure failure and establish a complete successful mapping before reporting missing/ambiguous identities or benchmark scores; do not treat a partial query as a regression result. See the [rehearsal blocker ledger](../validation/coverage-rehearsal-2026-10-03/qualification-blockers.json).

- Mastra merges non-reserved body and GET-query `requestContext` keys before application middleware and custom routes. Dropping client execution options in the chat handler does not clear those already-merged values. The legacy `user` key is client-mergeable too: bind resource ownership only from the verified token and clear it on missing or invalid authentication. Overwrite server-owned verification, diagnostic and prior-turn context on every request, including when diagnostics are disabled or the thread is new; HTTP fixtures must simulate the framework merge before testing forged context rejection.

- What Mastra passes an input processor's `messages` depends on the memory mode: with observational memory on it is the newest message alone, with it off (the default since October 2026) it is the recalled history plus the newest message. A gate that needs earlier turns must not read them from `messages`; unit tests that hand a processor a multi-message array hide this. The chat route reads the newest stored turns after the ownership check and sets them on the server-owned `chatPriorTurns` key, and `withPriorTurns` in `packages/agent/src/processors/prior-turns.ts` combines them with `messages` without counting a turn twice. Regressions belong at the HTTP level, in both memory modes (`tests/chat-prior-turns-http.test.ts`). The prompt-injection detector is built with `lastMessageOnly: true`; without it, memory-off recall costs one classifier call per recalled message and an old answer can block every later turn.
- A classifier that refuses an oversized input turns input size into a way through a gate that fails open. The Jev client rejects a body over 30,000 UTF-8 bytes, which about 9,990 CJK or Gujarati characters exceed; bound the bytes at the call site (`fitScopeWindow` in `packages/agent/src/jev/scope.ts`) and test with multi-byte text, not ASCII.
- The AI-SDK chat adapter does not perform the memory API's thread-ownership check before observational memory loads history. Binding the correct resource ID alone can still let a supplied foreign thread reach the observer. Check the existing thread's owner in the custom chat handler before starting execution; regressions must inspect observer/model inputs and stored history, not just the withheld public answer.
- Mastra's built-in memory routes do not fully enforce thread ownership on server 1.45.0 / libSQL 1.14.0. `POST /api/memory/threads` skips the owner check for an existing id and the adapter writes with `INSERT OR REPLACE`, so a create could re-own another user's thread; `GET /api/memory/threads/:id/messages?include=...` resolves message ids with no owner filter. Two local guards are load-bearing: the `saveThread` wrapper in `installMemoryReleaseGate` refuses a write that changes an existing thread's `resourceId`, and the execution gateway returns 400 for `include`. The release gate's read wrappers do not cover the second gap, because they only rewrite assistant text. Keep both guards, and the two-user case in `chat-memory-http.test.ts`, across Mastra upgrades until upstream scopes both paths.
- Thread request bodies are an allow-list in the execution gateway (`CREATE_THREAD`, `UPDATE_THREAD`, `CLONE_THREAD` in `packages/agent/src/execution-gateway.ts`): a rename takes `title` alone, a create takes `title`, `threadId`, `resourceId` and `agentId`, a copy takes `title` and `resourceId`, and any other key, `metadata` above all, is a 400. The framework stores client `metadata` as sent (create, update and clone all pass it through) and gives `metadata.mastra.om` to the observer and the model as system text, past every input guard. `resourceId` is allowed only because the framework's create schema requires the key, and must equal the signed-in user. A new field the web needs on a thread request must be added to these schemas or the request fails. The gateway reads the body from `c.req.raw.clone()`, as the framework's own context middleware does: reading it through `c.req.text()` consumes the stream, and the per-route `bodyLimit` then throws a 500 on any request without a `Content-Length` header (every `app.request` test, and chunked requests in production). Do not await `cancel()` on a cloned body's reader; it settles only when the original is cancelled too.
- Mastra's memory handlers answer a failure with the raw error text (`{"error":"SQLITE_ERROR: no such table: mastra_threads"}`). The gateway replaces every 4xx/5xx body from the `/api/memory/threads` routes with a fixed `{ error: { code, message } }` at the same status and logs `memory_route.failed` (5xx, with the original text) or `memory_route.refused` (4xx, status only, because a validation message can quote the request). The log names the route pattern, not the path, since the path holds a client-chosen thread id. When a thread route fails in a test, read that log line; the response no longer says why.
- Feedback comments go through `screenUserText` (`packages/agent/src/sensitive-data.ts`) and the route stores the text that function returns, so card PRIV-1 can turn a refusal into a redaction there without touching the route. `POST /feedback` also requires the caller to own the thread (`FeedbackRepository.ownsThread`); it does not check that the message exists, because the assistant row can be saved after the stream ends and a quick thumbs click would race it. `scripts/feedback-review.ts` therefore joins feedback to a thread with the same owner and prints a rating whose message id is not in the store with a placeholder. It reads answers through `guardMessage`, so it needs the `answer_release_keys` row from the same database; against a copy without that row every answer prints as the unverified-history notice.
- The memory release gate replaces named methods on the LibSQL memory store, so it is default-deny: `installMemoryReleaseGate` walks the store's whole prototype chain and throws at start-up when a function is in neither `GUARDED_MEMORY_METHODS` nor `PASS_THROUGH_MEMORY_METHODS` (`packages/agent/src/answer-release.ts`). A Mastra upgrade that adds a store method (`copyThread`, `updateThreadMetadata` and `updateThreadResourceId` arrive with core 1.67 / libSQL 1.23) therefore fails the agent tests and the boot until someone decides whether the method can return or persist assistant prose or change a thread's owner. Do not classify a new name as pass-through to get the server up without reading its adapter source; `updateThreadResourceId` in particular needs the same owner guard as `saveThread`.
- `GET /api/memory/threads/:id/messages` returns 40 messages unless `perPage` is sent, has no maximum page size, and with no `orderBy` returns the newest page. `orderBy` only picks which window of rows a page covers: Mastra's `MessageList` re-sorts every page oldest first, so a `DESC` request does not return rows newest first. Offsets carry no tiebreak on `createdAt` and shift when a message is stored between two requests, so page through `packages/web/src/lib/thread-messages.ts`, which de-duplicates by id and trusts `hasMore` rather than the page length. The client's response type omits `hasMore` and `total`; the server sends them.

Collect supplementary official identity evidence in a separate audit containing only the matching family, and validate the selected rows against a fresh locked registry snapshot. A rejected request is not evidence that the official page or payload is unavailable.

Restore the journals explicitly. Completed relocation proof also needs the installed payload, or its retained version plus the valid current artifact after a later revision.

- The crawler's historical `status='removed'` rows are not equivalent to evidence-backed retirement. `recovery-inventory` reports both active parse failures and removed sources without a durable retirement record; release preparation rejects either. In September 2026, checking only the nine recent parse failures hid 136 older undocumented exclusions. Do not grandfather those exclusions or create retirement evidence from a tombstone alone.

- The corpus release smoke must parse final verification events and released answer text. Response byte counts or the presence of source URLs can accept a withheld answer. Require a completed SSE stream, a passed/corrected outcome, and citations in the released text.
- A crawl discovery that lists nothing is a failure, not an empty success. Until October 2026 a 403, 404 or redesigned index returned an empty list, the family was stamped fresh and the crawl exited 0, so the release freshness gate passed on a stale corpus. Source modules now throw on a non-200 configured entry page, `discoverDocuments` fails a family that lists no documents or (default full crawls only) fewer than its `minDiscoveredDocuments` floor, `source_freshness` is stamped only for passing families and never on `--dry-run`, and `crawl` exits 3 when a required family failed. When a new source module handles a non-200 entry page, throw; do not return an empty list. A floor is a static number: if the agency legitimately shrinks a family below it, lower the floor in `packages/crawler/src/config.ts` rather than bypassing the check.
- Match listing entries by URL shape, not by the heading or field class around the link. The bulletin listing moved post titles from `h3` to `h2.field-content` in September 2026; the `.views-row h3 a` selector then matched nothing, the March fixture kept the tests green, and run #26 listed 96 bulletin documents instead of 388 and completed normally. `update-fixtures` overwrites several families' fixtures with untrimmed pages, so capture a dated, trimmed fixture beside the old one when markup changes and keep both under test.
- Index membership is an observation, never a status. Discovery was add-only until October 2026: a document the agency dropped from its index stayed `unchanged` and loaded as current unless its own URL returned 404 three times (the workstation registry held four versions of MA-2240). The crawler now records every URL a run returns in `source_listings` and stamps `source_index_checks` for an index page only when its family passed discovery with its floor enforced; `--dry-run`, `--source`, `--since-year` and failed families record listings but stamp no check. `read_index_listings` in `crawler_registry.py` derives de-listing at read time: the page's last complete check is newer than the row's last listing. One complete absence is enough, a row discovered from that page before listings existed counts as listed before the first check, and a document that reappears is restored by the next run that lists it, because nothing is stored. Manual rows, manifest seeds, rows whose page has no complete check, and every family except `dhhs_policy` are exempt. The loader skips a de-listed row as `delisted_from_index` and the audit treats that as an expected exclusion. Do not turn the signal into `status='removed'` or retirement evidence, and do not add a per-run column to `documents`: whole-row registry hashes must stay stable between runs.
- The DHHS index has two `data-slug` columns. `doc_categories` holds the section and sub-category; `doc_tags` holds the document kind and the agency's own `archived` mark on superseded documents it still publishes (137 of 921 rows on 2026-10-05, including the year-titled income and reserve tables). Until October 2026 the parser took the first slug it did not recognise as the category, so it discarded the Archived tag and stored the file-type slug (`pdf`, `xls`) as the category of every row without a sub-category. `parseDhhsPoliciesPage` now reads the category only from `doc_categories` and returns the tag slugs as `doc_tags`, which the crawl stores in `source_listings.tags` and overwrites on every listing, so a tag the agency removes is cleared. The loader writes `Document.archived = true` and `status = 'archived'` for a tagged row and leaves `answer_ready` alone. Filter on `archived`, not `status`: amendment detection later rewrites an archived change notice's status to `amendment`. Every search backend applies `notArchived()` in Cypher, coverage-frame routing drops archived documents, and `lookupPolicy` sorts them last; `getDocument`, `getSection` and the required-source lane in `frame/service.ts` still reach them, which is what keeps the scoped 2025 MAGI table answerable. The tag is the agency's and is incomplete (the undated MA-2252 is untagged); do not add title heuristics such as OBSOLETE to widen it.

- The crawler stores every State Plan Amendment number as `SPA NN-NNNN`, whatever the link text (`24-0028 ...`, `NC-24-0028 ...`, `SPA NC 24-0028 ...`); `initializeSchema` reshapes older bare rows. Policy lookup matches the whole number, so a bare `24-0028` finds nothing unless the `SPA ` prefix is added; `candidatePolicyNumbers` adds it. Clinical policy links without a comma (`1A-30 Spinal Surgeries`) take a leading-number fallback, and a link left without a number logs a warning rather than blocking a release. Stored numbers reach answers only after the next crawl and corpus release.
- Repeated section numbers inside one document are real in the parsed DHHS corpus (for example repeated `Attachment B` headers). Internal `Section.id` values need a deterministic duplicate suffix; `document_id + section_number` alone is not always unique.
- `lookupPolicy` matches a policy number exactly, compared as `policyNumberKey` does (upper-case, hyphens and spaces removed, so a typed `1-H` finds a stored `1H` and `MA 2180` finds `MA-2180`). It has no prefix or family match: `1A-2` used to return `1A-20` to `1A-28` with the newest sibling first, and coverage routing kept that first row. A partial number (`1A`, `3K`, "Policy 8") now returns nothing and siblings are left to search; do not add a prefix fallback. Derived revision rows (`document_type = 'change_notice'`, one per revision-table entry, sharing the policy's number) are excluded; they reach an amendment frame only through `getAmendments`, which is why `resolveAmendmentFrame` takes the newest row from the trail on the latest-revision route. Do not rank exact matches with an `any(pn IN $pns ...)` key in the `ORDER BY`: after the aggregating `RETURN` it fails on the pinned Neo4j 2026.05 with a planner assertion ("Expected a sorted plan"), and the stubbed unit tests cannot see it. Manual and form numbers are stored as prefix and digits (`DHB-5125`), with the form suffix only in the title, so `candidatePolicyNumbers` reduces `DHB-5125B` to `DHB-5125` and `preferTypedFormDocuments` lists the document whose title starts with the typed form first.
- `extractExplicitPolicyNumbers` reads a question's policy numbers by shape and cue, never from a list of known numbers. Clinical numbers with a numeric suffix (`1A-27`, `8A-1`, `1-O-1`) and manual or form numbers (`MA-2180`, `MA 2180`, `DHB-5125B`) count anywhere. A bare token (`3L`, `1-H`) counts only beside a cue: directly after "policy"/"CCP" (with "No.", "number", `#`, `(`), directly before "policy", after "under" when it ends the clause, next to a section reference ("section 5.6 of 3L", "3L section 5.6"), or in a list with a number that already qualified ("3L or 3L-1"). A bare numeral (`7`, `9`, `15`) counts only directly after "policy"/"CCP" and not before a unit ("policy 30 days"). Everything else is left to search, on purpose: `3D`, `3B` and `4B` are Hospice, PACE and Orthodontics, and "3D mammograms" anchored a coverage frame on Hospice. Looser cues the review suggested ("in", "of", "per", a following "covers"/"requires", two bare tokens joined by "vs") were left out because "stage 3b requires" and "3D vs 2D" satisfy them. Federal citations and State Plan Amendment numbers are not extracted; the model's `lookupPolicy` call resolves them. Two paths still read bare tokens: `queryMentionsPolicyNumber` in `rerank.ts` boosts hits of any policy whose number appears as a token, and the `policy_scoped` backend and exact-number boost compare the typed spelling to the stored one without the key.
- The graph stores no section position, and `collect()` over `HAS_SECTION` returns a document's sections in an arbitrary order that can change on a rebuild. `mapDocumentSections` therefore sorts every listing with `compareSectionListing` (section number in natural order, unnumbered first, then id), and `pickDocumentSectionsByTitle` uses the same comparator to break tied title scores. This is listing order, not document order: `Attachment A` follows the numbered sections wherever it appears in the source. Do not re-sort in the agent tools or rely on the order a fixture lists sections in; a frame that changes when a fixture's listing is shuffled is a bug. Golden frames recorded before this change were resolved under the old arbitrary order and need one deliberate re-baseline before any baseline-against-candidate comparison.

## Pipeline dead-code detection


`npm run lint -w @nc-medicaid/pipeline` runs **both** `ruff check src/` **and** `vulture src vulture_whitelist.py`. Vulture exits non-zero on *any* finding, so introducing dead Python code (or a vulture false positive) fails lint.

`packages/pipeline/vulture_whitelist.py` is a **curated** list of confirmed false positives — things vulture can't see are used: Click CLI commands (`@cli.command`), `HTMLParser` method overrides, driver/library attributes (e.g. `row_factory`), symbols referenced only by tests, and `SourceFamilyManifest` schema fields populated from `corpus-manifest.json`. If lint flags one of these for new code, add it to the whitelist.

Do **not** regenerate the whitelist with a bare `vulture src --make-whitelist` and commit it wholesale — that silently buries genuine dead code (it once would have hidden ~12 dead query constants). Use `--make-whitelist` to produce *candidates*, then triage: real dead code gets deleted, only true false positives go in the whitelist. The whitelist is excluded from ruff (`extend-exclude` in `pyproject.toml`) since its bare names would trip F821.

- Neo4j unknown-property queries return null with a warning rather than failing. Corpus diagnostics must read `Document.document_type` for the source family and assert actual `answer_ready` values; comparing two null `source_type` fields does not prove eligibility preservation.
A checkpointed SQLite corpus mounted read-only needs the guarded `immutable=1` adapter for every registry reader, including lifecycle snapshot measurement. SQLite `mode=ro` can still attempt locking sidecars and fail on the read-only mount. Check for nonempty WAL/journal files first; never use immutable reads against an active registry. Run container signal-drain tests with `--init` so orphaned descendants are reaped.

Give pytest parameters explicit short IDs when a fixture contains large text. With verbose CI output, the default string ID can print the complete 38 MB outlier body and stall log transport even though the test itself is fast. Keep full-size reconstruction assertions; shorten only the display ID.

- Overlapping embedding branches can auto-merge into incompatible APIs even after conflict markers are resolved. Keep one planner and recompute release coverage against its model, dimensions, tokenizer pin and exact chunk text/offsets; nonnull stored hashes and matching vector counts alone can accept another model or corrupted chunks. See [embedding input plans](../operations/embedding-input-plans.md).

- Mixed HTML/PDF bulletin families need markup sniffing even when the response omits or mislabels Content-Type; otherwise maintenance HTML can be accepted with a PDF extension. Missing-source boundaries must distinguish an original attachment request from supported procedural, dated-limit or pharmacist-payment questions. Keep mixed original/procedure and payment/authority requests covered by regressions.

### Jev validation and restoration

A scope benchmark can appear fast and harmless when every classifier call fails open. Qualification now requires zero failures in both arms, and the OpenAI benchmark reuses the production call and SDK retry defaults. Section-role adoption also requires an explicit reviewed allowlist; high probabilities alone do not qualify a role. Backup verification runs with system Python, so annotation artifact validation must remain standard-library-only and must not import the inference stack.

- Local corpus sections can exceed 38 MB. Full-graph identity reads with the default 1,000-record fetch can exhaust Neo4j direct memory, and sorting returned full bodies can exhaust its heap. Keep the current bounded, read-only identity normalizer and preserve unmatched evidence as misses. Jev sampling selects section IDs from metadata before reading full bodies; corpus fingerprinting streams input hashes. Oversized classifier inputs abstain rather than stopping later sections or truncating text.
- The July usage table is not sufficient confirmation for paid validation: the current official GPT-5.6 Terra page lists different rates. Freeze a separate confirmed campaign pricing file and preserve source URLs and the confirmation date before inference.

- Local Jev campaign directories are ignored and sit outside the default corpus backup. Browser progress is also not durable. Download reviewed JSON and run the explicit campaign snapshot command, which preserves caches and uses SQLite backup for a live ledger. Partial labels remain pending; full answers require the same reviewed corpus inputs and a passed frame gate.

- Editor HTML previews may disable sibling-file links or scripts even when a local dashboard renders. The Jev dashboard embeds all three forms in one file; open it in a real browser for labeling and JSON download, and check set switching as well as individual forms.
- AI review artifacts can share row IDs and label shapes with human reviews. Filtering imported text alone does not preserve label provenance: the browser or HTML exporter can silently drop an AI source marker. Reject AI-provenance files before importing/exporting human reviews, use separate audit storage, and test that rejected imports leave human drafts intact. Model agreement and a targeted disagreement sample remain diagnostic evidence.
- Canonical JSON sorts object keys, but derived report arrays retain iteration order. Building audit comparison rows from an unsorted decisions dictionary makes the first download import differ from re-importing its canonical saved copy. Sort fields before hashing derived report artifacts; exercise multi-field reviews with reversed key order in replay tests.

- Jev Choice confidence and the selected choice probability are independent; threshold the selected probability. See [Jev contracts](jev.md).
- Git worktrees do not inherit ignored `.env` files. Inspect the original checkout before reporting missing credentials; never print their values.

- Jev integration preserves main’s bounded whole-graph identity reader; older source-filtered readers and tests must not replace it. SQLite backup helpers use escaped file URIs so `#`, `?` and spaces in campaign paths do not change which database is read.

- Jev-enriched release graphs are immutable: source rewrites invalidate candidate annotation identity and reject stamped annotated releases. Source writes, enrichment and stamping share a transaction lock. Disabled stamping ignores diagnostic annotations; backups carry a label inventory outside the label directory so losing the whole archived directory still fails restoration. Retained release manifests independently require their referenced annotation manifests and caches, detecting a label directory lost before snapshotting.

- Run Linux process-supervision tests in Docker with `--init`. Without an init process, orphaned fixture children can remain zombies and make process-group drain checks time out even after TERM succeeds. CI runs on a normal host with process reaping.

- Backup inventories must describe captured bytes, not live files read again by tar. Snapshot label JSON with its inventory before archiving, and exclude live copies; snapshot release manifests as well as labels so later release updates and enrichment cannot change the archived bytes. Stamped annotation identity also survives disabled restamp attempts, which are rejected transactionally.

- Enabling Jev roles requires both a validated release stamp and a matching live annotation marker. Readiness alone does not gate every direct tool call; enforce the same identity in section retrieval and research recovery. Keep synthetic container headings free of label and release fields, which their child-aggregate records do not return.
