# RAG-Faithfulness Review — NC Medicaid Navigator (2026-06-11)

Expert review of the answer-trust layer: system prompt, answer-frame planning/prefetch, hallucination verifier, retrieval reranking, and eval methodology. Companion to `2026-06-11-remediation-plan.md`.

## Findings

1. **`packages/agent/src/processors/answer-frame-planning.ts:387-397` — critical — Planning processor injects pre-baked conclusions ("answer yes first") derived from keyword matches, not evidence.**
The pharmacy checklist writes into a system message: *"answer yes first from §X: the surfaced policy text says NC Medicaid may impose quantity limitations for episodic drugs"* — triggered by `isPharmacyQuantityPriorAuthQuestion()` (lines 80-85), a pure keyword match (`'quantity limit'` + `'drug'`). The section content is never checked to confirm it says that; `matchingSections()` matches on title/content substrings only. A novel question that hits those keywords but where the true answer is "no" (or where the surfaced section is a superseded variant) gets a system-prompt instruction asserting the wrong conclusion before the model reads anything. **Recommendation:** never inject conclusions into the plan; restrict plan messages to ordering/avoid hints; derive yes/no only from the model's own reading of section text.

2. **`packages/agent/src/processors/answer-frame-planning.ts:135-527` — high — Checklist machinery is overfit to the golden dataset, so eval gains don't generalize.**
The coverage/prior-auth/federal checklists hard-code the golden set's topics nearly one-to-one: telehealth speech-language (153-162, 238-277), ambulance not-covered (140, 306-315), congregate PCS (317-331), HCWD premiums (333-341, plus dedicated `isHcwdIncomePremiumQuery` rerank/route flags), MLR numerator/denominator (443-451, 511-521), waiver applications (452-484). A verifier comment references a specific question id (q-006, hallucination-verifier.ts:701). The 2.45 eval baseline therefore measures memorized routing for known questions, not behavior on unseen attorney questions. **Recommendation:** hold out a slice of the golden set the heuristics were never tuned against (or paraphrase/topic-shift variants) and report both numbers; treat any heuristic naming a specific section/topic as eval contamination.

3. **`packages/agent/src/processors/hallucination-verifier.ts:29-40,149-163` — high — Verifier strips `citationLink`/`url`/`lastRevised`/`federalRegisterCite` from getSection evidence, defeating two of its own checks.**
`getSection` returns all four fields (tools/read.ts:24-31) but the verifier's `GetSectionResult` type and `extractGetSection` serializer omit them. Consequences: (a) the verifier prompt's requirement that `suggestedCitation` "use the real citationLink present in the sources" (line 516) is unsatisfiable for section-level sources; (b) fabricated citation URLs in answers are undetectable; (c) revision-date claims the system prompt tells the agent to surface (prompt.ts:13) appear unsupported and risk `[unverified: ...]` wrapping. **Recommendation:** include all four fields in the serialized source block.

4. **`packages/agent/src/processors/hallucination-verifier.ts:444-449` — high — "Cited-first" source ordering never fires, so budget truncation can drop exactly the sources the answer cites.**
`buildSourceText` classifies a source as "cited" via `answerText.includes(s.key)` where `key` is a raw section ID (`sec:doc:...`) — but the system prompt forbids raw IDs in answers (prompt.ts:55). So `cited` is essentially always empty, ordering degenerates to tool-call order, and when the 120K-char budget truncates (line 459), the section backing the final answer (often read last) is the most likely casualty — producing false "unsupported" rewrites. **Recommendation:** match on `citationLink`/URL or `Policy <number> § <sectionNumber>` strings.

5. **Verifier + judge + blind detector all pass wrong-section citations — high — `hallucination-verifier.ts:513-517`, `judge.py:32`, `citation.py:70-71`.**
The verifier checks claims against the sources *as a whole* and that each claim has *an* inline link; it never checks that the link attached to a claim points at the section containing the supporting text. The eval judge treats a claim as supported "if it appears *anywhere* in Evidence"; `citation_quality` only asks whether citations are "specific," not correct; `_sentence_has_citation` counts any markdown link, fabricated or not. An answer that is factually right but cites the wrong section passes every layer — and attorneys quote the cited § in appeals. **Recommendation:** per-(claim, citation) verification against the specific cited section's content (the verifier already has section-keyed sources).

6. **`packages/policy-corpus/src/primitives/amendments.ts:28,49` — high — Undated amendment becomes the "authoritative document" due to Neo4j DESC null ordering.**
`ORDER BY amend.effective_date DESC` places null rows first; `authoritativeDocument = amendments[0]`. Any change notice missing an effective date outranks all dated notices and is presented as "the default current document" — which the system prompt instructs the agent to adopt (prompt.ts:51). Separately, treating the most recent change-notice *document* as authoritative is questionable: a notice amending one paragraph displaces the consolidated policy as the default citation target. **Recommendation:** null-guard the ordering; keep the base document authoritative while flagging which sections the latest notice supersedes.

7. **Retrieval has no supersession filtering — high — pattern across all backends (`fulltext.ts:22-23`, `chunk-vector.ts:14-16`, …).**
No backend filters or downranks by document `status`/effective date; superseded sections compete equally everywhere. The only defenses are the agent voluntarily calling `getAmendments` (prompted, unenforced) and the verifier's `latest_revision_only` rule, which fires only on the deterministic amendment lane *and* only when the superseding notice is already in sources. The common failure — a coverage question answered from a superseded section with no `getAmendments` call — passes verification, eval, and citation checks silently. **Recommendation:** carry `status`/`variantDate` into retrieval scoring (downrank superseded); make the verifier fail any answer citing a document with no `getAmendments` evidence in sources.

8. **`hallucination-verifier.ts:823-829,873-887` — medium — Unverified single-pass rewrite by a smaller model, applied to every text part.**
The corrected answer is generated by `gpt-5.4-mini` rewriting the *entire* answer, applied with no re-verification. A mini-tier model rewriting legal text can introduce its own paraphrase drift. The final `messages.map` replaces **every** text part of every assistant message — and the prompt encourages interim progress-update text parts (prompt.ts:72), so progress text gets clobbered. **Recommendation:** replace only the final text part; prefer span edits (marker insertion) over free rewriting, or re-verify the rewrite.

9. **`answer-frame-prefetch.ts:7-27` — medium — Frame is force-prefetched on every turn, including non-research follow-ups.**
Step 0 restricts `activeTools` to `resolveAnswerFrame` and forces the call with the latest user text verbatim. For "can you say that more simply?", the frame resolver runs keyword analysis on conversational text, produces a junk route/frame, and the planner injects a directive plan built from it — steering the answer off-course. **Recommendation:** gate prefetch on question-likeness; skip injection when frame primaries are empty/low-confidence.

10. **Planning layer doesn't earn its complexity — medium — `answer-frame-planning.ts` (700 lines) + `query-intent.ts` (483 lines) duplicated, drifted heuristics.**
E.g. `isYesNoCoverageQuestion` (planning :55-57) matches `/^(does|is|can)\b/` + `\bcover\b` while `isYesNoCoverageQuery` (query-intent :285-289) matches `/^(does|is|can|are|will|under)\b/` + `\bcover(s|ed|ing|age)?\b`; the `' nc '` padded-substring check (:590) misses "NC" at string start and "NC's". Route hints and plan checklists can disagree about the same question. **Recommendation:** delete duplicated detectors; pass `QueryAnalysis.flags` through the frame result; shrink checklists to route-level guidance (`buildRouteChecklist`, :575-610, is the defensible core).

11. **Eval hallucination dimension is circular and polluted by infra failures — medium — `judge.py:31-32`, `answer.py:511-520`.**
Unified evidence means anything the agent retrieved counts as support — wider (even wrong-document) retrieval mechanically raises the hallucination score. The judge sees the golden answer while scoring hallucination (leniency bias). Agent errors are scored `hallucination: 0` with no `None` exclusion, depressing averages and masking trends. **Recommendation:** score hallucination against evidence only (hide golden answer for that dimension); record agent-error rows as `None`/excluded with a separate availability metric.

12. **`rerank.ts:35-36,60-61` — low — Rerank disabled exactly where stakes are highest; ambiguity gate depends on unnormalized score scale.**
The `deterministic_evidence` lane (numeric/threshold questions) never reranks; the `ambiguous_top_hits` gate compares raw `scoreGap ≤ 0.2` across unnormalized hybrid scores. **Recommendation:** normalize before the gap test; allow deterministic-lane rerank within the already-selected document family.

13. **`prompt.ts:5-6` vs `54-63`; rule 7 vs plan rules — low — Duplicated citation spec; amendments-vs-no-widening contradiction.**
Citation format and "factual claim" definition specified twice. Evergreen rule 7 ("Check amendments for every document you cite") conflicts with the injected deterministic-route plan ("Do not widen beyond the current structured frame…"). **Recommendation:** single-source the citation spec; carve out getAmendments from no-widening.

14. **`finalize.ts:79-81` + `hallucination-verifier.ts:316-322` — low — Avoid-sections ship full content into context and count as verifier evidence.**
Up to 3 avoid-sections are hydrated with full content, occupying context (lost-in-the-middle pressure) and serialized into verifier source text — a claim grounded *only* in an avoid-section passes the factual check. **Recommendation:** emit avoid-sections as id/number/title only in both the frame tool result and verifier serialization.

## Top 3 highest-leverage answer-quality improvements

1. **De-contaminate planning from the golden dataset (1–2).** Strip conclusion-asserting and topic-specific checklist rules, keep route-level guidance, re-baseline on a held-out/paraphrased set. Until then the 2.45 number is not evidence the system works on unseen questions.
2. **Per-citation span verification (3–5).** Pass citationLink/section mapping into the verifier and check each claim against the specific section it cites. Converts the verifier from "did the agent say true-ish things" to "can an attorney safely quote this §".
3. **Structural supersession enforcement (6–7).** Fix the null-date authoritative bug, downrank superseded documents in retrieval, require `getAmendments` evidence for every cited document. Citing month-old superseded policy is the failure mode no layer reliably catches today.
