### security-appsec-01 — Thread takeover via POST /api/memory/threads overwrites any thread's owner (INSERT OR REPLACE)

- **Location:** `packages/agent/src/execution-gateway.ts:32`
- **Severity:** medium · **Kind:** security · **Effort:** S · **Status:** confirmed
- **Claim:** The owner of a thread can PATCH /api/memory/threads/:id (or POST /api/memory/threads) with a free-form `metadata.mastra.om` block. The installed @mastra/server 1.45.0 handler stores it in place of the existing metadata, and no application code wraps thread writes. Once the thread has active observations, @mastra/memory 1.26.1 emits om.currentTask and om.suggestedResponse as system messages on every model step of every later turn, and gives them to the observer model as prior metadata. The text is never seen by MessageLengthGuard, CoverageBoundaryProcessor, ScopeGateProcessor or PromptInjectionDetector, which inspect only the request's user message.
