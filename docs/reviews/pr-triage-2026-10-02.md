## Findings that change the priority

### Security fixes should come out of #129 first

The main branch pins `fast-uri` to 4.1.1 directly and through an override. The [official authority-injection advisory](https://github.com/fastify/fast-uri/security/advisories/GHSA-qw65-cvwx-89v3) lists 4.0.0 through versions below 4.1.4 as affected. This establishes an affected installed version, not that our application exposes that particular vulnerable input path. #129 proposes 4.2.1; extract a reviewed security update with the override and lockfile updated together, then run the existing production audit. Check the other proposed security/transitive updates individually rather than postponing them behind the AI SDK migration.

### Seven old red PRs share one unrelated baseline

Logs for #88, #89, #90, #91, #95, #96 and #97 each show `Found 73 errors` in pipeline Ruff lint. Current [pipeline configuration](../../packages/pipeline/pyproject.toml) explicitly selects the established rule sets and #141's current CI is green. This supports refreshing those PRs; it does not substitute for testing their new heads.

### Automated review failures need their own fix

The #140 review log reports `Workflow initiated by non-human actor: dependabot (type: Bot)`. This is a workflow policy failure, not a negative code review. Decide how the review workflow should handle Dependabot with narrowly scoped bot permissions/secrets; do not interpret this as a failed technical Docker test or allow arbitrary bots broadly. Refresh review checks along with CI.

### CI must cover stacked PRs

[CI](../../.github/workflows/ci.yml) has `pull_request.branches: [main]`. #114's clean merge state and successful review checks refer to its old #113 base and do not establish full test/build coverage. Before continuing this stack, either broaden the CI base-branch filter while preserving unconditional main push checks or create a current main-targeted PR that includes its prerequisite work. This gap was confirmed from #114's check list, not inferred from its test claims.

### Qualification evidence cannot live only in /tmp

#114 cites `/tmp/medicaid-chart-ab/hybrid/general-v1/hardest`; that directory is absent on the current machine. The older rejected-control source snapshot under `/tmp/medicaid-chart-ab/hybrid/deterministic-final/source-snapshot` is also absent. The cleanup did not remove those paths. The committed #114 implementation remains on its remote branch and in the recovery bundle, but those temporary receipts cannot now be independently checked. Recover a durable copy if one exists or rerun qualification. Keep reviewed receipts/source fingerprints in a durable evidence location, respecting private-source restrictions.

### Keep application runtime versions aligned

The [official Node release schedule](https://nodejs.org/en/about/previous-releases) lists Node 26 as Current and Node 22/24 as LTS at review time; it recommends LTS for production. [setup-node](https://github.com/actions/setup-node#breaking-changes-in-v5) and [checkout](https://github.com/actions/checkout#whats-new) separately require modern Actions runners for their embedded Node runtime. Upgrading an action's embedded runtime does not require upgrading our application from Node 22.
